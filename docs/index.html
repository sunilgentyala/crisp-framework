Open-source research prototype

Prove where a biometric stream came from, not just what it shows

CRISP (Cryptographic Root-of-trust Identity and Sensor Provenance) defends biometric authentication against injection attacks. It binds the capture path, the session, and the enrollment record together with TPM attestation, a post-quantum hybrid channel, and zero-knowledge matching, so a convincing deepfake is not enough to get through.

The problem

Most biometric systems trust the camera data they receive

Presentation attack detection targets artifacts held up to a sensor. Injection attacks replace the stream inside the operating system, after the sensor and before the checks run.

The stream is replaced

Virtual cameras (v4l2loopback, OBS Virtual Camera), malicious drivers, and library hooks feed synthetic video into the media pipeline as if it came from the sensor.

Detectors chase the generator

Deepfake and liveness detectors judge what a stream looks like. They are trained on generators they have seen, and they cannot say where the pixels originated.

CRISP changes the question

Instead of out-detecting the attacker, the verifier rejects any stream that cannot show fresh, hardware-backed evidence from an approved capture path.

Architecture

Four components between the sensor and the decision

Each component answers a different question. The decision module accepts only if every mandatory check passes, and any missing, stale, or unverifiable evidence causes rejection.

sensor frames + frame hash + verifier session nonce
SA

Sensor Attestation

A TPM 2.0 attestation key signs a quote over the frame data and the session nonce, so the verifier can tell evidence from an approved sensor key from evidence anyone else produced.

Targets virtual cameras and driver replacement
SET

Secure Telemetry

An X25519MLKEM768 hybrid key exchange feeds an AES-256-GCM channel whose associated data binds each message to its position in the session.

Targets tampering, replay, and reordering in transit
ZKBV

Zero-Knowledge Biometric Verification

A Groth16 proof shows that a probe is close to an enrolled template, so no raw template leaves the device.

Template privacy
BEM

Behavioral Entropy Monitor

KL divergence and spectral flatness over frame windows give a statistical signal for synthetic streams. It is an optional risk signal, not a cryptographic guarantee.

What has been measured so far

Component and protocol-level results from the real implementation, with their limits stated next to them.

Read these with their limits. The software-TPM numbers are a lower bound. The hardware-TPM number comes from one laptop and includes Windows driver overhead. The handshake overhead is an x86 loopback figure with no network. Groth16 proving was measured on x86 only and is preliminary. Channel attacks: 0 of 600 accepted

Ciphertext and tag bit flips, replay of an accepted frame, frame reordering, truncation, and decryption under a wrong session key were all rejected, 100 trials each.

What this does and does not show

It is a protocol-level soundness check with a software TPM and demo certificates. It does not measure biometric accuracy or liveness, and it does not cover an adaptive attacker with access to the sensor or the TPM.

Design goals

What the prototype is built to provide

These are design goals. The measurements above test components of them and are not a security proof.

  • Sensor bindingAccepted data should originate from an attested capture path.
  • FreshnessEvidence is bound to a single-use session nonce, so old evidence cannot be replayed.
  • Template privacyBiometric templates stay on the device. Only a proof is sent.
  • Fail closedMissing, stale, malformed, or unverifiable evidence causes rejection.
Quick start

Reproduce the benchmarks

Start with the SA (TPM attestation) benchmark. The benchmark guide covers SET, ZKBV, the attack matrix, and full prerequisites.

sudo apt install -y swtpm tpm2-tools python3-pip
pip install -r requirements.txt

mkdir -p /tmp/vtpm
swtpm socket --tpmstate dir=/tmp/vtpm --tpm2 \
  --server type=unixio,path=/tmp/vtpm/sock \
  --ctrl type=unixio,path=/tmp/vtpm/sock.ctrl \
  --flags not-need-init,startup-clear &

export TPM2TOOLS_TCTI="swtpm:path=/tmp/vtpm/sock"
tpm2_createprimary -C e -c /tmp/vtpm/primary.ctx
tpm2_evictcontrol -C o -c /tmp/vtpm/primary.ctx 0x81000001

python3 benchmarks/tpm_bench.py
python3 benchmarks/sa_set_attack_matrix.py 100
